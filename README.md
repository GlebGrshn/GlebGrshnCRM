# GlebGrshnCRM

Мини-CRM для заявок агентства: клиент пишет Telegram-боту, заявка сама становится лидом с тегом, команда работает с лидами в браузере и в Telegram.

- **Живая версия:** https://lushik.online — на странице входа есть подсказка «Как проверить CRM».
- **Клиентский бот** (заявки): [@JumpADSClients_bot](https://t.me/JumpADSClients_bot)
- **Бот команды** (CRM и уведомления для сотрудников): [@JumpADSCRM_bot](https://t.me/JumpADSCRM_bot)

Стек: Node.js 24 без внешних зависимостей (встроенный `node:sqlite`, `node:http`), SQLite, HTML/CSS/JS без сборки, Docker, Caddy.

## Как проверить за пять минут

1. Откройте https://lushik.online → **Регистрация**: любой юзернейм и роль, в поле Telegram — ваш @username.
2. Напишите клиентскому боту `/start` → имя → контакт → запрос.
3. В разделе **Лиды** появится заявка с тегом `telegram`. Добавьте свой тег и отфильтруйте список по нему; лида можно завести и вручную кнопкой «Добавить лида».
4. Напишите боту команды `/start` с того же Telegram: там лиды, задачи и уведомления — в том числе о только что оставленной заявке.

## Возможности

**Обязательная часть тестового задания**

- **Заявки из Telegram-бота.** Бот по шагам собирает имя, контакт (текстом или кнопкой «Поделиться телефоном») и запрос; лид появляется в CRM с тегом `telegram` только после всех трёх ответов. Повторная заявка не теряется: она сохраняется с тегом `возможный дубль`, клиенту о дублях бот не сообщает.
- **Ручное добавление.** Карточка лида: имя, контакт, компания, запрос, сумма, ответственный, заметки, теги. Дубли по контакту (телефон в любом формате, `@username`, `t.me/…`) или по имени и запросу требуют подтверждения.
- **Теги.** До 20 тегов на лид, фильтр списка и канбана по тегу, поиск по тегу в боте команды.
- **Обычный Telegram (пункт 2 задания)** не реализован: нужна авторизация личного аккаунта через MTProto. Подход описан в разделе «Ограничения».

**Сверх задания**

- **Бот команды** — CRM в Telegram: лиды по этапам и тегам, поиск (в том числе по телефону), карточка, новый лид, теги, смена этапа, «Взять себе», мои задачи, ответ клиенту. Сотрудник указывает Telegram при регистрации или в профиле и пишет боту `/start`; без юзернейма — одноразовая ссылка из профиля. Посторонним бот отвечает ссылкой на клиентского бота.
- **Уведомления в Telegram** обо всём: новые обращения (всей команде), сообщения клиентов (ответственному или всем), назначение ответственным, новые и переданные задачи, напоминания, общий чат и личные сообщения, подтверждённые оплаты.
- **Воронка и канбан:** Новый → В работе → Предложение → Сделка → Оплачено / Закрыт, перетаскивание карточек, фильтры (ответственный, источник, тег, оплата, сумма, даты) и сохранённые наборы фильтров.
- **Задачи** с исполнителем, сроком, приоритетом и напоминанием; **мессенджер** — общий чат, личные сообщения, переписка с клиентами через бота.
- **Т-Банк (тестовый режим):** счёт из карточки, ссылка на оплату уходит клиенту в бот, подтверждённая банком оплата переводит лид в «Оплачено»; напоминание о неоплате, рассылки подписчикам клиентского бота.
- **Автоматизации:** «событие → условия → действия» с паузами и журналом запусков.
- **Роли, архив и удаление лидов, история изменений, тёмная тема, демо-наполнение.**

## Роли

| Возможность | Администратор | Менеджер | Наблюдатель |
|---|---|---|---|
| Просмотр лидов, задач, чатов | Да | Да | Да |
| Создание и изменение лидов, задач, сообщения | Да | Да | Нет |
| Изменение чужих задач | Да | Только поставленных им или назначенных ему | Нет |
| Архив и удаление лидов, автоматизации, рассылки, роли | Да | Нет | Нет |

Права проверяются сервером. Личные сообщения видят только участники диалога. На живой версии включён тестовый режим `TEST_ROLE_SELECTION=true`: роль выбирается при регистрации и меняется в «Команда и роли». Без него новые пользователи становятся менеджерами, а последнего администратора убрать нельзя.

## Как устроено

```text
Клиент ──► клиентский бот ──┐                       ┌──► браузер (Caddy, HTTPS)
                            ├─► Node.js ◄─► SQLite ─┤
Сотрудник ◄─► бот команды ──┘   (один процесс)      └──► Т-Банк (счета, статусы)
```

- Один процесс Node.js обслуживает HTTP API, интерфейс и оба бота; данные — в одном файле SQLite.
- Боты получают обновления long polling'ом, без webhook. Исходящие сообщения идут через очередь в базе: при сбое сети они отправляются повторно, входящие обновления не дублируются.
- Диалог бота, смещение обновлений и создание лида сохраняются одной транзакцией, поэтому повторная доставка того же сообщения не создаёт второй лид.
- Пароли хешируются scrypt с солью, сессии хранятся на сервере (12 часов). Запросы с чужих сайтов отклоняются.

## Запуск локально

```bash
node scripts/setup.mjs   # создаёт .env из .env.example
npm start                # http://127.0.0.1:3000
npm test                 # интеграционные проверки
```

Первый зарегистрированный пользователь становится администратором. Без токенов ботов CRM работает, но Telegram недоступен. Демо-данные (5 сотрудников с разными ролями, 12 лидов на разных этапах, задачи): `node scripts/seed-demo.mjs`.

| Переменная | Назначение |
|---|---|
| `CLIENT_TELEGRAM_BOT_TOKEN`, `CLIENT_BOT_USERNAME` | клиентский бот (заявки) |
| `TELEGRAM_BOT_TOKEN` | бот команды; токен копируется целиком, вместе с цифрами и двоеточием |
| `TEST_ROLE_SELECTION` | свободный выбор роли (тестовый режим) |
| `TBANK_MODE`, `TBANK_TERMINAL_KEY`, `TBANK_PASSWORD` | тестовый терминал Т-Банка |
| `APP_PUBLIC_URL` | публичный HTTPS-адрес для уведомлений банка |
| `TRUST_PROXY` | `true` за reverse proxy: IP клиента и адрес сайта берутся из `X-Forwarded-*` |

## Публикация

Живая версия работает на VPS в Москве (Debian, Docker). Файлы для сервера лежат в `deploy/`, на сервере — в `/opt/glebgrshncrm`.

- **HTTPS:** `deploy/Caddyfile` — Caddy сам выпускает и продлевает сертификаты Let's Encrypt для `lushik.online` и `www.lushik.online` и проксирует оба адреса в CRM на `127.0.0.1:3000`. Перенаправление `www` на основной домен намеренно не используется: см. [docs/migration-access.md](docs/migration-access.md).
- **Обновление:** скопировать код в `/opt/glebgrshncrm` и выполнить `deploy/deploy.sh` — он пересобирает образ и пересоздаёт контейнер `glebgrshncrm`, данные остаются в томе `glebgrshncrm-data`. Docker читает `.env` только при создании контейнера, поэтому после правки `.env` тоже нужен `deploy.sh`.
- **Сеть:** контейнер работает в сети сервера (`--network host`): с этого VPS Telegram доступен только по IPv6, которого нет в обычной сети Docker. Порт 3000 открыт только на `127.0.0.1`.
- **Т-Банк** отдаёт сертификат НУЦ Минцифры. Корневой сертификат `certs/russian_trusted_root_ca.pem` (официальный файл с gu-st.ru) подключён только к запросам в банк. Если уведомление банка не дошло, CRM раз в минуту сама запрашивает статус неоплаченных счетов.
- **Резервные копии:** `deploy/backup.sh` ежедневно делает снимок SQLite без остановки CRM и хранит 14 дней; `deploy/restore.sh <файл>` восстанавливает базу, предварительно сохранив текущую.
- **Мониторинг:** `deploy/monitor.sh` каждые 5 минут проверяет сайт и подключение обоих ботов; о проблеме, длящейся две проверки, и о восстановлении сообщает администраторам в бот команды. Журналы контейнеров ограничены 3 × 10 МБ.

## Проверки

`npm test` — интеграционные тесты на встроенном `node:test`: регистрация и роли, сессии, дубли и идемпотентность, задачи и напоминания, приватность сообщений, оба бота и очередь Telegram (с подменённым транспортом), бот команды и уведомления, платежи Т-Банка и подписи уведомлений, автоматизации, удаление лидов, работа за прокси, восстановление после перезапуска.

`scripts/verify-*.mjs` — браузерные сценарии на Playwright; после последних изменений регистрации их нужно обновить.

## Ограничения

- **Пункт 2 задания (обычный Telegram)** не сделан. Подход: отдельный адаптер Telegram Client API (MTProto). Пользователь подключает аккаунт по телефону, коду и паролю 2FA, сессия хранится на сервере в зашифрованном виде. Адаптер слушает входящие личные сообщения, отбрасывает исходящие и служебные, дедуплицирует их по аккаунту, чату и сообщению и создаёт лид с источником `telegram_account`. Понадобятся выбор чатов, отключение аккаунта и проверки переподключения.
- Нет вложений, восстановления пароля, приглашений сотрудников, своих этапов и полей, аналитики.
- Клиентский бот не запрашивает согласие на обработку персональных данных (152-ФЗ) — для реального использования это обязательно.
- Интерфейс обновляется опросом раз в 5 секунд, а не через WebSocket.
